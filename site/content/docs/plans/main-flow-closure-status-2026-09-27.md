## 五、需要总控统一处理的事项

### 1. 接口/schema 同步（本分支按约定**没有** regen OpenAPI）
本分支的后端改动**不新增、不改动对外接口**：`app/core/db.py`（连接级 PRAGMA）与 `backend/tests/**` 都不影响 OpenAPI。
但**基线 `df33a33` 的 `front/openapi.json` 已滞后 21 条路径**（含需求二 drama-plan 全套、asset-profiles、asset-workbench、reference-regenerate 等），
且整棵 `front/src/services/generated/**` 因此陈旧。**本分支未 regen**（按用户约定交总控）。
另：`regen` 一旦追平，会立刻暴露 `ChapterShotEditPage.tsx:182` 的
`product` / `AssetKind` 类型不匹配（商品线读取侧枚举同步的漏网，旧客户端把它藏住了）。

### 2. 共享文件冲突
- 仓库**提交了机器相关绝对路径符号链接**：`front/node_modules → /Users/apple/Documents/Jellyfish/front/node_modules`、`backend/.venv → …/Jellyfish/backend/.venv`。
  主仓 venv 的 editable 安装指向 `jellyfish-pr41`，**任何使用该链接的 worktree 都在跑 pr41 的代码**（实测 `jellyfish-ad-mvp` 即如此）。
  本 worktree 为隔离已换成真实依赖（`front/node_modules` 真实安装、`backend/.venv-local`），**收尾时会还原符号链接以保持工作树干净**。
- `front/pnpm-lock.yaml` 与代码不兼容：lockfile 钉 `antd 5.10.0` / `typescript 5.2.2`，而代码用到 `Card.styles`（antd ≥5.14）与新版 TS 的模板字面量推断；pr41 实际装的是 `antd 5.29.3` / `TS 5.9.3`。
  也就是说 **`pnpm install --frozen-lockfile` 装出来的树过不了 `tsc`**。本分支用临时 `pnpm.overrides` 对齐到可用版本（**未改 package.json / pnpm-lock.yaml**），此项建议总控统一处理。
- `@types/node` 不是声明依赖（lockfile 里只是可选 peer），干净安装会缺。
